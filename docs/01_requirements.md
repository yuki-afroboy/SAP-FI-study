## 1. 背景と目的

### 1.1 背景
- SAP を中心にビジネスを展開するコンサルティング会社に所属し、現在は **テストフェーズ** のプロジェクトに参画中。
- 今後のキャリアで **要件定義・設計・構築・テスト・稼働後保守の全フェーズ** に関与する見込み。
- 一方で現状の SAP FI 知識は限定的であり、単純な伝票作成にも時間を要する。

### 1.2 目的
SAP FI の知識を体系的に習得し、**プロジェクトを技術面で牽引できる状態**に到達する。
「操作できる人」ではなく「**設計を決められる人**」になることを目的とする。

---

## 2. 到達レベルの定義（As-Is / To-Be）

「プロジェクトを引っ張れる」を測定可能にするため、以下のレベルを定義する。

| Lv | 名称 | 状態 |
|---|---|---|
| L0 | 未着手 | 用語が分からない |
| **L1** | **操作見習い（現在地）** | 手順書があれば伝票入力できる。なぜその画面・項目なのかは説明できない |
| L2 | 自立オペレータ | 標準機能の全体像を説明でき、手順書なしで業務処理・残高照会・簡単な調査ができる |
| **L3** | **設計者（3ヶ月後の目標）** | IMG 設定と業務上の挙動の因果を理解し、Fit&Gap で「標準で吸収するか／アドオンするか」を根拠付きで判断できる |
| L4 | リード（最終目標） | 業務要件から会計設計を組み立て、他モジュール・税務・決算・移行まで整合を取り、チームを技術指導・レビューできる |

### 2.1 目標設定の考え方（重要な前提）
- 学習投下時間は **週10時間 × 12週 = 約120〜130時間**。
- この時間で到達可能なのは **L3（設計判断ができる）＋ 得意領域1つで L4 相当** が現実的な上限。
- **L4 の完全到達には実プロジェクトでの意思決定経験が不可欠**であり、学習だけでは代替できない。
  したがって本プロジェクトのゴールは「L3 到達」＋「L4 へ向かうための地図と自走できる仕組みの獲得」と定義する。
- テストフェーズ参画中という状況は、実務課題を教材化する好機であり、これを積極的に活用する。

## 3. スコープ

### 3.1 対象領域（優先度 A：深掘り）

| # | 領域 | 主な内容 |
|---|---|---|
| A-1 | GL・組織構造・伝票制御 | 会社コード／原価元価／元帳、勘定コードマスタ、伝票タイプ・転記キー・項目ステータス、自動転記、為替換算、Universal Journal (ACDOCA) |
| A-2 | AP / AR と購買・販売連携 | 仕入先／得意先マスタ（BP）、請求計上、支払プログラム F110、入金消込、MM-FI（GR/IR・価格差異）、SD-FI |
| A-3 | 月次・年次決算プロセス | 期間クローズ、再評価、残高照合、財務諸表バージョン、決算タスク（Fiori）、CO との連携 |
| A-4 | AA 固定資産・銀行・日本固有 | 償却計算、取得／除却、銀行勘定、支払方法、消費税・インボイス制度、電子記録債権 |

### 3.2 対象領域（優先度 B：基礎レベルで押さえる）
- CO（管理会計）の概要と FI との境界
- MM / SD の業務フロー概要（FI 影響部分に限る）
- 移行（残高移行・マスタ移行）、権限、監査対応の基礎

### 3.3 対象外
- ABAP の実装スキル（ただしテーブル構造・BAPI・調査に必要な読解は対象）
- FI 以外のモジュールの設計スキル
- SAP 認定資格の受験対策（**資格取得は目標に含めない**方針を採用）

## 4. 制約条件・前提

| # | 区分 | 内容 | 対応方針 |
|---|---|---|---|
| C-1 | 環境 | 実機は会社の S/4HANA 環境。**カスタマイズ（SPRO）を自由に触れる保証はない** | 設定演習は「IMG 画面の閲覧＋設定意図の説明」で代替。可能なら自由に触れる検証クライアントの確保を早期に打診する（→ 課題管理） |
| C-2 | **機密保持** | 本リポジトリは GitHub 上にあり、**顧客固有情報を記載してはならない** | 顧客名・会社コード・金額・マスタデータ・独自要件は一切書かない。実務課題は必ず**抽象化・匿名化**して教材化する。判断に迷う場合は書かない |
| C-3 | 時間 | 週10時間、12週間 | 週次サイクルを固定し、消化ではなく定着を測る |
| C-4 | 業務状況 | テストフェーズ参画中。繁忙により学習時間が確保できない週が発生しうる | 各週の課題は「必須（コア）」と「発展」に分離し、必須のみでも進行可能にする |

## 5. 学習方式（実現手段）

### 5.1 基本方針
教材を読むだけでは L3 に到達しない。**想起（思い出す）と設計判断（決める）を強制する仕組み**を本体とする。

### 5.2 週次サイクル（10時間の内訳）

| 工程 | 時間 | 内容 |
|---|---|---|
| ① 対話セッション | 2h | 週テーマの講義＋質疑。理解度に応じて深度を調整する（**選択された進め方**） |
| ② 実機ハンズオン | 3h | 実際に S/4HANA で操作。手順と気付きを記録 |
| ③ 自習 | 3h | 教材・SAP Help・Note の読解、周辺調査 |
| ④ 記録と想起テスト | 2h | ノート化、一問一答、設計課題への回答 |

### 5.3 進め方
- **毎回対話しながら進める**方式を採用。セッション単位で「講義 → 問答 → 演習 → 振り返り」を回す。
- 対話は流れて消えるため、**毎セッション必ずリポジトリへノートとして残す**ことを必須とする（これを守らないと本方式は破綻する）。

### 5.4 リポジトリ構成（成果物の置き場）

```
docs/        本書、カリキュラム、進行ルール
knowledge/   トピック別ナレッジ（体系・設定と挙動の因果）
hands-on/    Tコード／Fiori アプリの操作記録、シナリオ演習
drills/      一問一答・設計判断ドリルと解答
casebook/    不具合・トラブル事例集（匿名化済み）
progress/    習熟度マップ、週次ログ
```

## 7. スケジュール概要（12週）

| 週 | テーマ | 到達目標 |
|---|---|---|
| W1 | FI 全体像・組織構造 | 会社コード／原価元価／元帳／通貨の関係を図示して説明できる |
| W2 | Universal Journal と GL マスタ | ACDOCA 一元化の意味、勘定コードマスタの各項目が何に効くか説明できる |
| W3 | 伝票制御① | 伝票タイプ・転記キー・項目ステータスの三者関係を説明し、狙った入力制御を設計できる |
| W4 | 伝票制御② | 自動転記・為替換算・振替・未決済／消込の仕組みを説明できる |
| W5 | AP（債務） | 仕入先マスタ、請求計上、支払プログラム F110 の設定と実行を一人称で回せる |
| W6 | MM-FI 連携 | 購買発注〜入庫〜請求照合の仕訳と、GR/IR・価格差異の発生原因を説明できる |
| W7 | AR（債権）と SD-FI | 得意先マスタ、請求、入金消込、販売伝票からの会計連動を説明できる |
| W8 | AA（固定資産） | 償却領域・資産クラス・取得／除却／償却実行の一連を説明・実行できる |
| W9 | 銀行会計・日本固有 | 支払方法、銀行勘定、消費税／インボイス制度、電子記録債権の扱いを説明できる |
| W10 | 月次・年次決算 | 決算プロセス全体を一人称で回し、CO 連携と財務諸表出力まで説明できる |
| W11 | 不具合調査（テストフェーズ直結） | 伝票番号から原因（設定／マスタ／プログラム）を切り分ける調査ルートを確立する |
| W12 | 統合演習 | Fit&Gap 模擬課題で設計判断と根拠を文書化し、レビューを受ける |

※ 進捗と理解度に応じて再計画する。消化を目的とせず、受入基準の達成を優先する。

## 8. 完了判定基準（受入基準）

第12週時点で以下を満たすことをもって L3 到達と判定する。

| # | 基準 | 判定方法 |
|---|---|---|
| AC-1 | 主要 Tコード／Fiori アプリ 約60本を、手順書を見ずに目的・前提・結果を説明し実行できる | ランダム抽出10本の実演 |
| AC-2 | FI の主要 IMG 設定 30項目について「何を設定し、どの業務挙動に効くか」を説明できる | 口頭試問（ランダム10項目） |
| AC-3 | 月次決算の一連（期間クローズ→再評価→残高照合→財務諸表）を一人称で回せる | シナリオ演習の完走 |
| AC-4 | Fit&Gap 模擬課題10本で、標準／アドオンの判断と根拠を文書化できる | 設計レビューで指摘が致命的でないこと |
| AC-5 | 伝票番号を起点に、設定・マスタ・テーブル（BKPF / BSEG / ACDOCA など）から原因を特定する調査手順を説明できる | 障害シナリオ演習 |
| AC-6 | 習熟度マップで対象領域 A-1〜A-4 のすべてが Lv3 以上 | 自己評価＋口頭試問による裏付け |

## 9. リスクと対策

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| R-1 | 実機でカスタマイズを試せない | 設定と挙動の因果が腹落ちしない（L3 到達の最大の障壁） | 検証クライアント確保を早期に打診。並行して「設定値 → 挙動」の対応表を教材で補い、既存設定のリバースエンジニアリング演習で代替する |
| R-2 | 対話中心のため記録が残らない | 復習不能・定着しない | セッションごとのノート化を必須の完了条件とする |
| R-3 | 業務繁忙で学習が止まる | 計画倒れ | 各週を「必須／発展」に分離。2週連続で未達なら計画を縮小再設計する |
| R-4 | 「読んで分かった気になる」 | 実務で手が止まる | 想起テストのスコアを記録し、正答率で判定。読解時間より演習時間を多く配分する |
| R-5 | 顧客情報の混入 | **重大なコンプライアンス違反** | 教材化時は必ず抽象化。commit 前に自己チェックを行う |
