# 学習ラボ 設計書

要件定義書 5.2「学習ラボ」の設計。実装は `app/` 配下。

---

## 1. なぜ作るのか

要件定義 4.1 の環境マトリクスのとおり、**「設定を変える → 業務挙動が変わる」を確認できる環境が存在しない**。
ここは L3（設計判断ができる）の核心であり、ここが埋まらないと 3ヶ月かけても L2 止まりになる。

学習ラボはこの一点だけを担当する。実機の代替ではない。

| 学ぶ対象 | どこでやるか |
|---|---|
| 業務を回す手触り、実データ、Fiori の画面 | 検証環境 |
| IMG の実物、設定項目の場所と名称 | サンドボックス |
| **設定と挙動の因果関係** | **学習ラボ** |

---

## 2. 構成

ビルド不要。`app/index.html` をブラウザで開くだけで動作する（ローカルファイルでも可）。

```
app/
  index.html
  css/style.css
  js/data.js       伝票タイプ・転記キー・項目ステータス・勘定マスタ・税コードなどの初期値
  js/engine.js     転記エンジン（チェックと自動転記、および設定トレースの生成）
  js/store.js      進捗の永続化（XP・連続日数・間隔反復・設定の保存）
  js/missions.js   ミッション定義と達成判定
  js/drills.js     ドリル問題
  js/ui.js         画面
```

進捗と設定は `localStorage` に保存される。ホーム画面から Markdown を書き出し、`progress/` にコミットして履歴を残す。

## 3. 再現している SAP の挙動

| 挙動 | 対応する実機の設定 |
|---|---|
| 伝票タイプによる許可勘定タイプの制限、参照番号必須 | OBA7 |
| 番号範囲からの伝票番号採番 | FBN1 |
| 会計期間のオープン／クローズ判定 | OB52 |
| 転記キーによる借方／貸方・勘定タイプの決定 | OB41 |
| **転記キー × 勘定 FSG の項目ステータス合成**（必須・任意・抑止／矛盾検出） | OB41 × OBC4 |
| 調整勘定への直接転記の禁止、自動転記のみ勘定の保護 | FS00 |
| 取引先マスタの調整勘定への自動記帳 | BP（FD02 / FK02） |
| 税コードによる税額行の自動生成、内税／外税の違い | FTXP / OB40 |
| 貸借バランスチェック | — |
| BKPF / BSEG / ACDOCA への記帳結果の表示 | — |

### 3.1 意図的に再現していないもの

簡略モデルであることを明示する。以下は実機で確認する。

- 消込（未決済項目管理）、支払プログラム F110 の提案・実行
- 為替換算、並行元帳、グループ通貨
- MM / SD からの自動仕訳生成、勘定決定（OBYC など）
- 権限チェック、ワークフロー、バッチ入力

## 4. 設定トレース

本ラボの中心機能。転記のたびに、その伝票に効いた設定を順に列挙する。

```
1. 伝票タイプ SA（総勘定元帳伝票）  OBA7
   許可勘定タイプ = S/A/K、番号範囲 = 01、参照番号 = 任意
2. 会計期間管理  OB52
   会計年度 2026 の期間 1〜12 がオープン
3. 取引先 V-1001 の調整勘定  BP / FD02・FK02
   明細1 は取引先マスタの調整勘定 211000（買掛金）へ自動転記
4. 項目ステータス合成（明細1）  OB41 × OBC4
   転記キー 31 の項目ステータス と 勘定 211000 の FSG G067 をリンク
...
```

エラー時も同様に、**どの設定が拒否したのか**と、どう直せるか（そして直すべきかどうか）を返す。

## 5. 継続性の設計（要件 N-1〜N-5）

| 仕掛け | 内容 |
|---|---|
| ミッション | 達成条件を機械判定する実践課題。**エラーを起こすこと自体が達成条件**の課題を含める（設定矛盾 FS001 を自分で発生させる、など） |
| 核心課題 | 「設定を変えないと絶対に達成できない」課題に `核心課題` の印をつける。ここが L3 への入口 |
| XP とレベル | 転記成功・ミッション達成・ドリル正解で加算 |
| 連続学習日数 | 1 日 1 回でも触れば継続。ゼロの日を作らないことを目的にする |
| 間隔反復 | 正解すると次の出題が先送りされ、間違えると翌日また出る（SM-2 簡略版） |
| 学んだことの開示 | ミッション達成後に「この課題で学んだこと」を開示する。実務での意味づけを必ず添える |

### 5.1 設計上の注意

XP やレベルは**目的ではなく計測手段**である。受入基準（要件定義 8 章）は口頭試問と実演で判定するものであり、
ラボの XP が高いことは L3 到達の証明にはならない。この点を混同しないよう、ホーム画面では習熟度マップ（自己評価）を並置している。

---

## 6. 公開方法

- ローカル：`app/index.html` をブラウザで開く
- GitHub Pages：リポジトリ設定 → Pages → Source を「GitHub Actions」にすると、`.github/workflows/pages.yml` が `app/` を公開する

スマートフォンからも開けるため、移動時間にドリルだけ回す使い方ができる（要件 N-4）。
