# W1: FI の全体像・組織構造・会計年度・通貨

到達目標：**会社コード／原価管理領域／通貨／会計年度の関係を、白紙に図を描いて説明できる。**

---

## 1. FI は何を守る仕組みか

FI（Financial Accounting）は **外部報告** のための仕組みである。株主・税務当局・監査法人という
「社外の他人」に対して、法律で決められた形式で数字を出す責任を負う。

ここから FI の設計思想が全部出てくる。

| FI の性質 | そこから来る仕様 |
|---|---|
| 外部に対して正しさを証明する必要がある | 伝票は削除できない。取り消すには逆仕訳を切る |
| 法人単位で報告する | 会社コードが最重要の組織単位になる |
| 国ごとに法律が違う | 会計年度・通貨・税・勘定科目が国別に分かれうる |
| 期を締めたら動かせない | 転記期間の開閉という仕組みが要る |

対して CO（管理会計）は **内部管理** のための仕組みで、社内の意思決定が目的だから
「正しさ」より「役に立つこと」が優先される。だから期をまたぐ配賦もするし、実績と計画を並べる。

> **設計者としての意味**：顧客が「この数字を見たい」と言ってきたとき、まず問うべきは
> 「それは社外に出す数字か、社内で判断に使う数字か」。FI で受けるか CO で受けるかが、そこで決まる。

S/4HANA では両者が ACDOCA という 1 つのテーブルに同居するようになったが、**目的が違うという設計思想は消えていない**。

## 2. 組織単位の全体像

```
クライアント（Client）                     … システム全体。マスタを共有する最上位
 ├ 会社コード（Company Code / BUKRS）      … ★FI の中心。独立した財務諸表を作る法的単位
 │   ├ 事業領域（Business Area）           … 旧来の内部区分。S/4 では新規採用は非推奨
 │   ├ 利益センタ（Profit Center）          … 損益責任の単位。CO 側だが FI 伝票にも付く
 │   │   └ セグメント（Segment）           … 利益センタから導出される外部報告用の区分
 │   └ 与信管理領域（Credit Control Area）  … 与信限度の管理単位
 ├ 原価管理領域（Controlling Area / KOKRS） … ★CO の中心。会社コードを 1 つ以上割り当てる
 └ 会社（Company / RCOMP）                 … 連結の単位。会社コードを 1 つ以上割り当てる
```

購買組織・販売組織・プラントなどは MM/SD 側の単位で、いずれも会社コードに紐づく。
**「その組織単位は誰の要求で存在するのか」**を常に問うこと。法的要求なら会社コード、
管理要求なら利益センタ、というように出どころが違う。

### 2.1 会社コード

- 独立した貸借対照表と損益計算書を作る単位。通常は **1 法人 = 1 会社コード**
- 会社コードごとに決まる主なもの：国、現地通貨、会計年度バリアント、勘定コード表、税手続き（国経由）
- 確認 Tコード：**OBY6**（グローバルパラメータ）。ここを読めば、その会社コードの素性がほぼ分かる

> **よくある議論**：「支店ごとに会社コードを分けたい」。分ければ財務諸表は分かれるが、
> 伝票も勘定も分かれ、社内取引が会社間取引になり、運用が重くなる。
> 法的に別法人でないなら、利益センタやセグメントで受けるのが定石。

### 2.2 原価管理領域と会社コードの関係

CO の単位である原価管理領域には、**複数の会社コードを割り当てられる**（クロス会社コード原価会計）。
グローバル案件では「全世界で 1 つの原価管理領域」という構成がよく採られる。

ただし複数割当には条件がある。ここが試験にも実務にも出る。

| 条件 | 内容 |
|---|---|
| 会計年度バリアント | 割り当てる全会社コードで**通常期間の数が一致**していること（特別期間の数は異なってよい） |
| 勘定コード templates | 業務用勘定コード表が同一であること |
| 通貨 | 原価管理領域の通貨タイプの設定と整合すること（全社同一通貨か、グループ通貨を使うか） |

- 定義：**OX06** ／ 割当と管理指標：**OKKP**

> **設計判断**：1 原価管理領域にまとめると、全社横断の原価分析や社内配賦がやりやすくなる。
> 反面、会計年度や勘定コード表を各国で揃える必要が出る。
> 「分析の一体性」と「各国の自由度」のトレードオフであり、どちらが正解ということはない。
> **顧客に説明すべきはこのトレードオフそのもの**であって、結論だけ押し付けてはいけない。

### 2.3 利益センタ・セグメント・事業領域

- **利益センタ**：損益責任の単位。S/4HANA では FI 伝票にも標準で付き、ACDOCA に格納される
- **セグメント**：外部報告のセグメント情報。標準では利益センタマスタから導出される
- **事業領域**：古くからある内部区分。貸借対照表を分けられるが、自動転記で値が入りにくく整合が取りづらいという弱点がある。**S/4HANA では新規採用は推奨されない**

> 顧客が「事業領域で分けたい」と言ったとき、それが本当に事業領域である必要はまずない。
> 何を見たいのかを聞き直し、利益センタ／セグメントに寄せられないか検討するのが最初の一手。

## 3. 会計年度バリアント（OB29）

会計年度を「何期間に分けるか」「いつ始まるか」を定義する。

| 概念 | 内容 |
|---|---|
| 通常期間（Posting Period） | 通常 12。月次決算の単位 |
| 特別期間（Special Period） | 最大 4。年度末の決算調整を、12 月の数字を汚さずに追加計上するための枠 |
| 年度シフト | 会計年度と暦年がずれる場合の補正。4 月始まりなら 1〜9 月は当年、10〜12 月は翌年度扱い、という具合 |
| 年度依存 | 期間の区切りが年ごとに変わる場合（週次会計など）に使う |

代表例：**K4**＝暦年 1〜12 月＋特別期間 4、**V3**＝4 月〜翌 3 月（日本・インドで使う）。

- 会社コードへの割当：**OB37**

> **グローバル論点**：日本とインドは 4 月始まり、米国や中国は暦年、企業によっては 7 月始まり。
> 会社コードごとに会計年度バリアントを変えられるので**国ごとの年度差は吸収できる**。
> ただし 2.2 のとおり、同じ原価管理領域に入れるなら通常期間の数は揃える必要がある。
> 「12 期間で統一できるか」は、グローバルテンプレートの初期に必ず論点になる。

### 3.1 特別期間を使うか

特別期間は「決算整理仕訳を通常の 12 月と区別したい」という要求に応える機能。
使えば監査対応で説明しやすくなるが、レポートで期間 13〜16 を意識する必要が出る。
使わない企業も多い。**要件がないなら増やさない**のが原則。

## 4. 転記期間バリアント（OB52）

「いつまで転記させるか」を制御する。月次決算の締め作業そのもの。

- 勘定タイプ別に開閉できる：`+`（全体）／`A` 資産／`D` 得意先／`K` 仕入先／`M` 材料／`S` 総勘定元帳
- 期間範囲を 2 つ持てる。1 つ目は全員向け、2 つ目は**許可グループ**を持つ担当者だけが使える
  → 「一般ユーザーには締めるが、経理の一部だけ数日延長する」という運用ができる

> **実務での定番の問い**：「締めた後に前月の伝票を入れたい」。
> このとき答えるべきは Yes/No ではなく、**「誰に、どの勘定タイプで、いつまで開けるか」**という設計の話。
> 許可グループの存在を知っているかどうかで、回答の質が変わる。

学習ラボの IMG タブで期間を絞り込むと、範囲外の転記が拒否される挙動を確認できる（ミッション M05）。

## 5. 通貨

FI では 1 つの伝票が複数の通貨で同時に記帳される。

| 通貨 | 意味 |
|---|---|
| 伝票通貨（Transaction Currency） | 取引そのものの通貨 |
| **会社コード通貨**（現地通貨 / 通貨タイプ 10） | その法人が財務諸表を作る通貨。必須 |
| **グループ通貨**（通貨タイプ 30） | 連結のための共通通貨 |
| 追加通貨 | 硬貨・指標通貨など。S/4HANA では自由に定義できる通貨枠が増えた |

換算に使うのが**為替レートタイプ**（M＝標準の平均レート、B＝銀行買、G＝銀行売 など）と、
レートテーブル（**OB08**）、通貨間の換算比率（**OBBS**）。

S/4HANA では元帳・通貨・会計原則の設定が **FINSC_LEDGER** に統合されている。
（ECC を知っている人にとっては OB22 まわりが吸収された形。）

> **グローバル論点**：伝票通貨と現地通貨が違えば必ず換算差が出る。
> 「いつのレートで換算するか」「差額をどの勘定で受けるか」は W4 の自動転記で扱う。
> ここでは **「1 伝票が複数通貨を同時に持つ」** という構造だけ確実に押さえる。

## 6. この週の設計判断リスト

W12 の Fit&Gap 演習につながる論点。今の時点で答えを出す必要はないが、問いの形を覚えておく。

1. その組織単位は、法的要求から来ているか、管理要求から来ているか
2. 会社コードを分ける必要は本当にあるか。利益センタで受けられないか
3. 原価管理領域を全社共通にするか。そのために会計年度と勘定コード表を揃えられるか
4. 特別期間を使うか。使うなら誰がどう運用するか
5. 期間を締めた後の例外転記を、誰にどこまで許すか
